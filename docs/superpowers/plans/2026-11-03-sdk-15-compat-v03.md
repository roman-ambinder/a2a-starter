# SDK 15: A2A 0.3 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Every subagent runs on model `sonnet` (see "Execution notes" at the end). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One .NET agent serves A2A 0.3 and 1.0 clients from the same handler, at the same URLs, and the .NET client calls 0.3 agents through the normal `IA2AClient` API. All 0.3 code lives in two packages, `Ambinder.A2A.Compat.V0_3` (models and client) and `Ambinder.A2A.Compat.V0_3.AspNetCore` (server). The core has no 0.3 type, method name or field name, and a test enforces that.

**Spec (binding):** `docs/superpowers/specs/2026-11-03-sdk-15-compat-v03-design.md` (cited below as "spec").
**Work plan (binding):** `docs/superpowers/specs/2026-11-03-sdk-00-work-plan.md`. This plan follows its decisions on 0.3 ("A2A 0.3"), C14 (the two-package split) and B12 (shared code as linked internal source).
**Names and layout:** package 01's package map, `docs/superpowers/specs/2026-11-03-sdk-01-packaging-release-design.md` Design §1 (the rows for `Ambinder.A2A.Compat.V0_3` and `Ambinder.A2A.Compat.V0_3.AspNetCore`).

**Architecture:**
- **Server.**
  - Core seams used:
    - 03's `IA2AVersionDispatcher` claims version `0.3` (which includes an empty header) and handles the whole JSON-RPC or REST request.
    - 03's `IAgentCardContributor` adds 0.3 interfaces and legacy fields to the served card.
    - 08's `IPushPayloadFormatter` writes 0.3 push bodies.
  - Compat converts 0.3 requests to 1.0 models and calls the core `IA2ARequestHandler`, which is 09's middleware pipeline, with `A2ACallContext.ProtocolVersion = "0.3"`. It then converts the results back.
  - gRPC 0.3 is its own gRPC service, generated from the vendored v0.3.0 proto. Teams opt in with `MapA2AGrpcV0_3()`.
- **Client.**
  - Package 10's `IAgentCardReader` reads 0.3-only cards into 1.0 `AgentCard` models.
  - An `IA2ATransportFactory` with `ProtocolVersions = ["0.3"]` creates 0.3 transports for JSON-RPC, REST and gRPC. The `A2AClient` wrapper adds interceptors, auth, retries and tracing around them unchanged.
- **Shared code.** The 0.3 models, the source-generated `V0_3JsonContext` and the converters live once under `src/Compat.V0_3.Shared/`. They are linked as `internal` into both compat packages (B12 pattern). Package 01 rule 6 forbids `InternalsVisibleTo` between shipped packages, so this is the only way both packages can use them without making them public (see decision D5).

**Tech stack:** .NET 10, `System.Text.Json` source generation with hand-written `Utf8JsonReader`/`Utf8JsonWriter` converters for the `kind` unions, ASP.NET Core, `Grpc.AspNetCore` / `Grpc.Net.Client` / `Google.Protobuf` / `Grpc.Tools` (central versions), xUnit v3, and the package 16 interop harness.

## Owner decisions needed before execution

While reading the other packages' plans, the planner found gaps between the seams they define and what spec 15 needs. Each item gives a recommendation. **The executor does not start Tasks 8–18 until the owner has answered D1–D5.** D1 changes public API in `Ambinder.A2A.AspNetCore`, so it must merge **before package 02's `1.0.0-rc.1` freeze** (decision D7).

**D1. The dispatcher has no resolved caller, tenant or binding.** **Approved by the owner on 2026-11-03.** The package 03 plan's Task 8 now builds `A2AVersionDispatchContext`, the context overload and `IA2ACallerResolver` as recommended below.
- What spec 15 says: "the dispatcher runs after the core has resolved the agent and run ASP.NET authentication and authorization … compat calls the same `IA2ARequestHandler` … with an `A2ACallContext` whose `ProtocolVersion` is `0.3`".
- What 03's plan defines: the seam is `HandleAsync(HttpContext http, A2AAgentRoute agent, string version, CancellationToken ct)`. It gives no caller and no tenant, and it does not say whether JSON-RPC or REST called it.
- What 07's plan defines: the code that resolves the caller and tenant is internal (`TransportRequest.ResolveCallerAsync`, `CreateCallContext`). Compat cannot call it, and copying it would break the "exactly the same auth and owner rules" promise.
- The gRPC 0.3 service has the same problem: it needs the caller for a `ServerCallContext`.
- **Recommendation:** add one public context type, and give the dispatcher an overload that takes it. The core fills it after agent resolution and caller resolution.

```csharp
namespace Ambinder.A2A.AspNetCore;

public sealed class A2AVersionDispatchContext
{
    public required string AgentName { get; init; }
    public required AgentCard PublicCard { get; init; }
    public required string Binding { get; init; }          // "JSONRPC" or "HTTP+JSON"
    public required string RequestedVersion { get; init; } // raw header value; "" when absent
    public required A2ACaller Caller { get; init; }
    public required string Tenant { get; init; }
    public required PathString RestPath { get; init; }     // REST remainder after the agent's REST base; empty for JSON-RPC
}
// IA2AVersionDispatcher.HandleAsync(HttpContext http, A2AVersionDispatchContext context, CancellationToken ct)
```

  For gRPC 0.3, add a public `IA2ACallerResolver` in `Ambinder.A2A.AspNetCore`, `ValueTask<(A2ACaller Caller, string Tenant)> ResolveAsync(HttpContext http, string agentName, string? requestTenant, CancellationToken ct)`. The core transports also use it, so there is one implementation.
- **If the owner declines the resolver:** gRPC 0.3 on the server (spec Goal 6, server half) stays open, and Task 14 is not started.

**D2. Where the core calls the dispatcher.** **Approved by the owner on 2026-11-03.** The package 03 plan's Task 8 Step 4 calls the dispatcher after agent and caller resolution, before the body read and the REST operation resolution.
- 03's plan calls it "before `EnsureSupportedVersion`". In today's JSON-RPC endpoint that is *after* the body has been read and parsed. In today's REST endpoint it is *after* operation-route resolution, so a 0.3-only path such as `/v1/tasks/{id}/pushNotificationConfigs` would get 404/405 before compat sees it.
- **Recommendation:** the core calls the dispatcher right after agent resolution and caller resolution, **before** reading the body (JSON-RPC) and **before** resolving the REST operation (REST). This is a change in 03's code; it contains no 0.3 literal, so the core purity rule still holds.

**D3. Server SSE loop and heartbeats are internal to `Ambinder.A2A.AspNetCore`.** **Approved by the owner on 2026-11-03, as recommended.** The package 14 plan (Task 18) and the package 09 plan (Task 12) now put this code in `src/Shared/Sse/`.
- Package 14's plan has `SseFrameWriter`, an internal `ISseFrameFormat`, and the "flush when idle" loop. Package 09's plan adds heartbeats inside that loop.
- Spec 15 says keep-alives "come from the core SSE writer".
- **Recommendation:** move the loop, the frame writer and the heartbeat timer code to `src/Shared/Sse/` and link it as `internal` into `Ambinder.A2A.AspNetCore` and `Ambinder.A2A.Compat.V0_3.AspNetCore` (B12). Compat supplies its own `ISseFrameFormat`.
- **Rejected alternative:** a second SSE loop in compat. It would mean two heartbeat implementations, which would drift apart.

**D4. Client SSE parser is internal to `Ambinder.A2A.Client`.** **Approved by the owner on 2026-11-03, as recommended.** The package 10 plan (Task 6) creates the parser in `src/Shared/Sse/`.
- Package 10 replaces it with a `PipeReader` parser that enforces limits (PD3).
- **Recommendation:** move it to `src/Shared/Sse/` and link it into `Ambinder.A2A.Client` and `Ambinder.A2A.Compat.V0_3` (B12), so 0.3 streams get the same limits and the same parser.

**D5. Shared 0.3 code between the two compat packages.** **Approved by the owner on 2026-11-03, as recommended.**
- Spec "Package contents" puts the models and converters in `Ambinder.A2A.Compat.V0_3`, and also says they are internal.
- The server package needs them too, and rule 6 forbids `InternalsVisibleTo` between shipped packages.
- **Recommendation:** put them in `src/Compat.V0_3.Shared/` (no csproj) and link them into both compat packages as internal source. There is a precedent: `src/Grpc.Shared/` (01 rule 4). The cost is two internal copies; the benefit is that no 0.3 type becomes public (spec Non-goals: "A public set of 0.3 model types or converters").

**D6. Client options that are not in spec 15's public API list.** Spec acceptance says the PublicAPI files hold "only the listed types". **Approved by the owner on 2026-11-03, as recommended.** (a) No `SendVersionHeaderToV0_3` option. (b) Add `AddV0_3Support(this A2AClientOptions)`.
- (a) Spec "Client" mentions an option `SendVersionHeaderToV0_3 = false`. **Recommendation:** do not ship it in 1.0. The behavior is fixed: no `A2A-Version` header goes to a 0.3 agent. Add the option later only if someone asks for it.
- (b) Non-DI callers (`A2AClient.ConnectAsync`) have no way to add 0.3, because spec 15 lists only `AddV0_3Support(this IA2AClientBuilder)`. Package 10 gives gRPC both forms (`builder.AddGrpcTransport()` and `options.AddGrpcTransport()`). **Recommendation:** add `public static A2AClientOptions AddV0_3Support(this A2AClientOptions options)` to `V0_3ClientExtensions`, for the same reason. It is one extra public member, and the PR names it.

**D7. Timing against the API freeze.** **Approved by the owner on 2026-11-03, as recommended.** The package 02 plan's deferred task D1 checks it before `rc.1`. Package 02 moves every API line to `PublicAPI.Shipped.txt` at `1.0.0-rc.1`. After that, D1's seam change is a breaking change. **Recommendation:** land D1–D4 in their owning packages' code before rc.1, even if the rest of package 15 lands after it.

Decisions this plan makes itself (no owner input needed; each is marked *(plan writer's call)* where it is used):

- **A 1.0-shaped request without a version header** gets the same 1.0 `VersionNotSupported` response bytes as a server without compat, apart from the message text. Spec 15 has compat answer it with "send `A2A-Version: 1.0`". This keeps the core TCK's missing-header test green with compat installed (acceptance: "Core TCK still passes with compat installed").
- **The 0.3 `kind` unions** (parts, file content, stream events, results) use hand-written `Utf8JsonReader` converters, not `[JsonPolymorphic]`. That way `kind` need not come first, the REST ProtoJSON form without `kind` is accepted (spec "tolerant read"), and the converters are AOT-safe.
- **The extended card on 0.3** (`agent/getAuthenticatedExtendedCard`, REST equivalent) is converted by compat itself from the 1.0 extended card model, using the same card writer that the contributor uses. This settles 03's open item 5 for compat: contributors only run on the public card endpoints.

## Global constraints (every task)

- **Core purity.** No file under `src/Ambinder.A2A.{Protocol,Server,AspNetCore,AspNetCore.Grpc,Client,Client.Grpc}/` or `src/Shared/` may contain a 0.3 method name, a 0.3 field name or a 0.3 type. Core changes needed by D1–D4 are version-neutral. The purity test (Task 3) runs on every PR.
- **One task is one task.** There is no separate handler or store for 0.3. Compat only converts, then calls `IA2ARequestHandler`.
- **Lossless conversion.** Every field that has a 1.0 home is carried: file names, media types, metadata, `extensions`, `referenceTaskIds`. Fields with no 1.0 home are listed in `docs/spec-decisions.md` and in the docs page. A converter that drops a mappable field is a bug.
- **No hang.** Every 0.3 stream compat serves ends with a `final: true` status update when a task exists. The compat client ends a stream at `final: true` or when the server closes it.
- **Source of truth.** The vendored v0.3.0 files (Task 1) are the reference for every 0.3 name, shape, code and path. When this plan or the spec disagrees with them, the vendored files win. Write the difference in `docs/spec-decisions.md` and in the PR.
- **Public API.** Only the types in spec "Public API", plus D1/D6 if the owner accepts them. Everything else is `internal`. PublicAPI files are edited by hand (02).
- **Performance.** Source-generated JSON and AOT-safe code. 1.0 requests never reach compat code (the dispatcher is reached only for non-1.0 versions).
- **Builds:** `TreatWarningsAsErrors`, `ConfigureAwait(false)` in `src/`, central package versions, and XML docs on every public member.
- **Commits:** `feat(compat):`, `test(compat):`, `docs(compat):`, `ci(compat):`, one concern each, ending with the session's attribution lines.
