# SDK 06 Multi-Instance Cluster Layer: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Read "Execution notes" at the end before starting.

**Goal:** Make a group of pods behave like one A2A server. The store records which pod runs a task. Other pods forward cancel, subscribe and continue requests to that pod over authenticated internal HTTP/2. Leases (package 09) handle a pod that dies. No Redis or message bus. The core depends only on four seams, so a Redis backend can plug in after 1.0.

**Architecture:**
- **Core seams** in `Ambinder.A2A.Server` (namespace `Ambinder.A2A.Server.Cluster`): `ITaskEventBus`, `ITaskRouter`, `ITaskForwarder`, `ClusterCallContext`, and their small helper types. The single-pod defaults are `LocalTaskEventBus` (today's `TaskEventBroker`, made internal) and `LocalTaskRouter` (always local, no store reads).
- **`TaskManager`** loads the task and checks owner and tenant first, then asks the router. A `Forward` route calls the forwarder. A forward that fails falls back to the durable cancel flag in the store. Forwarded calls (`IsForwarded`) never route again.
- **`Ambinder.A2A.Cluster`**:
  - `AddA2ACluster()` and the startup checks
  - `ClusterTaskRouter`, backed by the store and an instance-lease cache
  - `HttpTaskForwarder` and the streaming proxy
  - internal endpoints on `InternalPort` only
  - the `IClusterPeerAuthentication` seam
  - cancel polling, the shutdown participant, the `a2a-cluster` health check and metrics
  - No Azure dependency.
- **`Ambinder.A2A.Cluster.Entra`:** `AddEntraPodAuthentication()`. Pods get a token through `WorkloadIdentityCredential`. The receiver validates it with package 07's Entra scheme and requires the app role `A2A.Cluster.Peer` (C6).
- **Tests:**
  - `ClusterTestHarness` runs N in-process Kestrel hosts on port 0 with one shared store and test-only `SharedKey` pod auth.
  - A fake-Redis backend proves the seams (Goal 9).
  - The TCK runs through a round-robin proxy.
  - A nightly `kind` job runs 3 replicas with chaos.

## Global constraints

- **Single pod pays nothing (Goal 10).** Without `AddA2ACluster()`:
  - the router is `LocalTaskRouter`, which never reads the store;
  - no `ITaskForwarder` is registered;
  - there is no internal listener;
  - no extra store call happens on any operation;
  - no sequence tracking or side tables are kept.

  Task 3 adds a store-call-count test that proves this.
- **No check is skipped (anti-goal, B5).**
  - Routing happens only after the receiving pod has loaded the task and checked owner and tenant.
  - The full middleware pipeline runs once, on the receiving pod.
  - The owner pod runs only peer authentication, tracing, the forwarded-call accounting (Task 6) and the handler.
- **One hop only.** A call with `IsForwarded = true` is never routed again. An internal request whose `HopCount` is not 1 is rejected with 400.
- **Never a silent gap (Goal 4).** Every stream either delivers every event in sequence order, or ends with an error whose ErrorInfo reason is `TASK_STREAM_INTERRUPTED` or `SUBSCRIBER_TOO_SLOW`.
- **No publisher ever waits.** `Publish` uses `TryWrite` only. No proxy stage blocks another subscriber.
- **Time comes from `TimeProvider`.** This covers poll loops, backoff, idle timeouts and caches. No `DateTime.UtcNow`, `Task.Delay` without a `TimeProvider`, or `Thread.Sleep` in `src/`.
- **Never recorded:** tokens, `Authorization` values, pod credentials, HMAC keys, and message, part or artifact content. This applies to spans, logs, metrics and exception messages (`docs/production.md` §6, 07's scrubber assertion). `ClusterCallContext` never carries an access token or user assertion.
- **Internal endpoints are internal.**
  - They are mapped with `RequireHost("*:{InternalPort}")` **and** checked with an endpoint filter that requires `HttpContext.Connection.LocalPort == InternalPort` (see "Plan's own calls" 4).
  - Peer authentication runs before the body is read.
  - A failure gives 401, and nothing executes.
- **JSON is source-generated.** Protocol types go through `A2AJson` typed accessors. Cluster wire types go through a `ClusterJsonContext` in `Ambinder.A2A.Cluster`.
- **Public API rules (02):**
  - `Add…` methods go in namespace `Microsoft.Extensions.DependencyInjection`.
  - Public models are `sealed record` with `init` properties.
  - XML docs go on every public member; implementer-facing interfaces get `<remarks>` with their guarantees.
  - Every new public symbol is added to `PublicAPI.Unshipped.txt`.
- **Error texts are fixed** where spec 06 gives them. Tests assert them exactly.
- **Tests:** no fixed ports (Kestrel listens on port 0), no sleeps. Wait on `TaskEventLog`, `TaskCompletionSource` gates or `FakeTimeProvider.Advance`. Container tests skip visibly without Docker unless `A2A_REQUIRE_CONTAINERS=1`, the same rule as 05.
- **Branch:** `feat/sdk-06-cluster` from `master`. Open one PR per phase (A–D); each must be green on its own.

## Review focus

1. **A forwarded cancel or subscribe for a task the caller does not own.** The receiving pod answers `TaskNotFound` before any route or forward (Tasks 4, 18).
2. **Host header spoofing.** A request to the **public** port with `Host: x:8090` and an internal path gets 404 (Task 10).
3. **A forward to a pod that just lost the run.** It answers 409 `not-runner`. The sender re-reads and retries once, then answers "The task moved between servers; retry." (Tasks 4, 11).
4. **Two continuations of one interrupted task on two pods.** Exactly one runs; the other gets `UnsupportedOperation` (Task 18).
5. **A subscriber on pod B while the runner pod A dies.** B's client gets the final event (`Fail`) or `TASK_STREAM_INTERRUPTED` (`Restart`) within 30 s, never a hang (Tasks 12, 18).
6. **One stalled client among 50.** The others get each event within 100 ms. Only the stalled one is dropped, with `SUBSCRIBER_TOO_SLOW` (Tasks 2, 12, 18).
7. **A forwarded continuation when the owner pod is at its execution limit.** The client gets `SERVER_BUSY` from the owner pod, and B releases its own reservation (Task 6).
8. **An app that sets its public port only through `ASPNETCORE_URLS`.** Adding the internal listener must not silently drop the public port. Startup fails with the documented fix (Task 7).
9. **A paused runner that wakes up.** Its write fails on the version check. It stops its run. There is no double completion (Task 18).
10. **The release check.** Single-pod benchmarks are unchanged (Task 23), and the core has no reference to `Ambinder.A2A.Cluster` (Task 7).

## Plan's own calls (for owner review)

These are not fixed by spec 06. Each is marked where it appears:

1. **`TaskSubscription.ReadSequencedAsync` and `SequencedEvent`** (Task 1). Spec §7.2's `TaskSubscription` yields `StreamResponse` only. The proxy's order check (§7.7) and a distributed bus's snapshot join both need the event's `Sequence`. Without it, a Redis-style bus cannot join a snapshot without a gap or a repeat.
2. **`IDistributedTaskEventBus` marker** (Task 1). It implements the §7.3 startup check "must not be replaced by a backend that already distributes events" without type-name checks.
3. **Forwarded-call accounting** (Task 6). B5 skips limits on the owner pod. The owner pod still takes an execution slot for a forwarded continuation, and a stream slot for a proxied stream (§7.7 "count proxied streams on both pods"). Rate limits apply once, on the receiving pod. The receiving pod releases its own reservation before forwarding.
4. **`RequireHost` plus a local-port filter** (Task 10). `RequireHost` alone matches the `Host` header, which a client can set. The local-port check makes "internal paths are 404 on public ports" hold against spoofing.
5. **Kestrel public-listener check** (Task 7). An explicit internal `Listen` makes Kestrel ignore `ASPNETCORE_URLS`. Startup fails with the fix instead of silently dropping the public port.
6. **Error and startup texts the spec does not give** (Tasks 2, 4, 5, 7): the slow-subscriber message, "being recovered", "could not be reached", the pod-auth, loopback and bus-conflict startup messages, and the loop rejection.
7. **The internal listener does not close on its own** (Task 14). After runs settle, internal endpoints answer 503 `SERVER_SHUTTING_DOWN`. The listener closes with the host. Kestrel has no supported way to close one listener early.
8. **`kind` uses a test-only host image with `SharedKey`** (Task 21). Entra workload identity cannot run in `kind` (O3), and `SharedKey` must not ship (C6), so the nightly `kind` job deploys `tests/Ambinder.A2A.Cluster.KindHost`. Real Entra pod auth runs in the AKS live leg only.
9. **`TaskNotRunnerException` and `TaskForwardFailedException` are public** (Task 1). They cross from the core to `Ambinder.A2A.Cluster`, and 01 rule 6 forbids `InternalsVisibleTo` between shipped assemblies.
10. **Subscribe joins the snapshot by sequence on every bus** (Task 3). It subscribes first and skips events at or below the snapshot's sequence. The local lock is kept on one pod, so behavior there is unchanged.
