# SDK 05 Store Contract and Durable Stores: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Read "Execution notes" at the end before starting.

**Goal:** Replace `ITaskStore` and `IPushConfigStore` with the store contract of spec 05 (optimistic concurrency, tenant-scoped keys, owner-scoped paging, delete, retention, outbox rows, instance leases). Ship four kinds of store that all pass one conformance suite: bounded in-memory (default), EF Core on SQLite, PostgreSQL and SQL Server, and Azure Cosmos DB.

**Architecture:**
- The contract lives in the core package `Ambinder.A2A.Server`, namespace `Ambinder.A2A.Server.Stores`. It has no database dependency.
- The core owns all protocol validation: page size, history length and page tokens. Page tokens are a linked source file under `src/Shared/Stores/` (package 01 rule 10, B12). Stores get typed, already-validated `TaskQuery` records.
- `TaskWriter` becomes the single write path: build the record, run `ITaskWriteContributor`s (outbox rows), `CreateAsync` or `UpdateAsync(expectedVersion)`, publish, notify observers. A conflict means reload, then retry once or stop the run.
- The per-task in-process lock table is reference-counted and frees its entries.
- EF Core: one provider-neutral package plus three provider packages, each with its own migrations and an idempotent SQL script.
- Cosmos DB: one container with hierarchical partition key `/tenant`, `/agent`, `/owner`. A task and its outbox rows are written in one `TransactionalBatch`.
- Conformance suite: framework-neutral case catalogs plus abstract xUnit v3 classes, in `tests/Ambinder.A2A.Stores.Conformance`. Every shipped store's test project derives from them, exactly as a third party would.

**Tech stack:**
- .NET 10 (`global.json`), C# latest, nullable on, `TreatWarningsAsErrors`, central package management (`Directory.Packages.props`)
- EF Core 10.x: `Microsoft.EntityFrameworkCore.Relational`, `.Sqlite`, `.SqlServer`, `.Design` (tools only), and `Npgsql.EntityFrameworkCore.PostgreSQL` 10.x
- `Microsoft.Azure.Cosmos` 3.x
- xUnit v3 (the repo already pins `xunit.v3`), `Microsoft.Extensions.TimeProvider.Testing` (`FakeTimeProvider`)
- Testcontainers for .NET (`Testcontainers.PostgreSql`, `Testcontainers.MsSql`, `Testcontainers.CosmosDb`) for container tests. They use random host ports, never fixed ones (B2).
- BenchmarkDotNet (only if package 14's project is missing; see Task 30)

**Specs (binding):**

## Global constraints

- **No database in the core.** `Ambinder.A2A.Server` must not reference EF Core, Npgsql, SQLite, SQL Server or Cosmos packages, or ASP.NET Core (01 rule 2). Task 29 adds the test that fails if it does.
- **No DB types in the contract.** No `DbContext`, `Container` or `IQueryable` in any `Ambinder.A2A.Server.Stores` signature. Store packages may use their DB SDK types only on their own registration and model methods (02's allow-list).
- **Stores do no protocol validation.** No store throws `A2AException`. Stores throw only `A2AStoreException` (§7.8) and `OperationCanceledException`.
- **Time comes from `TimeProvider`.** No `DateTime.UtcNow` / `DateTimeOffset.UtcNow` in `src/` (02's banned-API file). Stores take times from their arguments (`now`) or from the record; the core fills `CreatedAt`, `UpdatedAt` and `ExpiresAt`.
- **JSON is source-generated.** Serialize protocol types with `A2AJson`'s typed `JsonTypeInfo<T>` accessors (B12). No `JsonSerializer` overload without type info.
- **Ordinal ids.** Every comparison of task ids, owners, tenants, lanes and config ids is ordinal. EF columns that hold them use a binary/ordinal collation (Task 16).
- **XML docs on every public member** (CS1591 is an error in `src/`). Implementer-facing interfaces carry a `<remarks>` with the guarantees an implementer must give (02 §docs rule). The remarks text is given in Task 2.
- **Records:** public models are `sealed record` with `init` properties and no positional constructor (02 rule). `TaskRunner`, `TaskWrite`, `TaskPage`, `StoredPushConfig` and `PushConfigPage` are property records too (owner decision 2026-11-03; spec 05 §7 now shows them that way). The only exception is the six small key structs spec 05 defines as positional `readonly record struct`s (`TaskKey`, `OwnerScope`, `TaskCursor`, `TaskRef`, `CreateResult`, `OutboxStats`); keep them exactly as the spec shows them. Plan 02's API review checklist lists them as a named exception.
- **Package 02 rules** (`docs/superpowers/plans/2026-11-03-sdk-02-public-api.md`; 02 may land before or after this plan): the in-memory store classes (`InMemoryTaskStore`, `InMemoryPushConfigStore`, `InMemoryOutboxStore`, `InMemoryInstanceStore`) are `internal`, because users get them through `AddA2AServer` (02 default for default implementations; 02's `PublicSurfaceTests` checks them by name). Their options classes stay public. New log calls in `src/` use `[LoggerMessage]` with fixed `EventId`s: `Ambinder.A2A.Server` uses its 02 block (1000–1999); each new store package takes the next free block of 1000 and records it in `docs/policies/versioning.md` (or in the PR if that page does not exist yet). Code outside `Ambinder.A2A.Protocol` never uses `A2AJsonContext`; use the `A2AJson` typed accessors, or `A2AJson.Options.GetTypeInfo(typeof(T))` before 02's Task 2 lands. If `tests/Ambinder.A2A.PublicApi.Tests` exists, it passes; add a row for each new store package to its `AllowedForeign` table if one is missing.
- **Error texts are fixed** where spec 05 gives them (Task 13, Task 22, Task 27). Tests assert the exact text.
- **Style:** match the surrounding code: file-scoped namespaces, `ConfigureAwait(false)` in `src/`, short XML doc sentences, plain English in docs.
- **Branch:** work on `feat/sdk-05-stores`, created from `master` after 01 is merged. One PR per phase (A–G below) is fine; each PR must build and pass all tests alone.

## Review focus

Reviewers (and the final review subagent) check these scenarios first:

1. **Two writers race on one task** (2 × 1,000 updates). No lost update on any store; every loser gets `StoreErrorKind.Conflict` (Task 6 case `concurrency.racing-writers`).
2. **Tenant B guesses tenant A's task id.** Get, update, delete, list and push-config calls under tenant B never see it (Task 6 group `tenant`).
3. **A client retries a new-task `SendMessage` with the same `messageId`.** It gets the first task back; the handler runs once. A continuation with the same `messageId` is not deduped (Task 12).
4. **A failure between the task row and its outbox rows.** Neither is written (Task 6 case `outbox.atomic-with-task`, durable stores).
5. **A webhook that always fails** must not block another push config of the same task (lane-head rule, Task 7 case `outbox.lane-head-per-lane`).
6. **A paused pod wakes up and writes.** Its write fails with `Conflict`; the writer stops its run because `Runner.InstanceId` is not this instance (Task 11).
7. **A page token from one filter reused with another filter** gives `InvalidParams` "pageToken does not match this query; start again without pageToken" (Task 3).
8. **`statusTimestampAfter` equal to a task's timestamp** includes that task (inclusive, `a2a.proto:695-697`; Task 6 case `list.timestamp-from-inclusive`).
9. **A long-running pod with the default in-memory store** stays under the memory ceiling and the lock table returns to 0 entries (Tasks 10, 31).
10. **Push credentials at rest.** The stored bytes of EF and Cosmos push configs never contain the plain credential (Task 7 case `push.credentials-protected-at-rest`).

// A2AStoreException.cs
namespace Ambinder.A2A.Server.Stores;

/// <summary>What went wrong in a store call.</summary>
