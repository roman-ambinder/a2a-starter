# SDK package 08: Push notifications and webhook receiver, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task, with every subagent on model `sonnet` (see "Execution notes" at the end). Steps use checkbox (`- [ ]`) syntax for tracking.

**Milestone:** M1.

**Goal:** Push delivery becomes durable and at-least-once over package 05's outbox, with per-config ordering, retries, and a dead-letter state. Every delivery sends the spec-standard credentials. The signature JWT becomes an optional, declared A2A extension, backed by a pluggable signing key with rotation and a JWKS of all active keys. Delivery can go through an HTTP proxy without weakening the SSRF guard. A new package, `Ambinder.A2A.Push.Receiver`, gives receivers verification, task matching and dedupe in about 10 lines.

**Spec (binding):** `docs/superpowers/specs/2026-11-03-sdk-08-push-design.md`. Where this plan and the spec disagree, the spec wins. Stop and report the conflict; do not pick one silently.

- `docs/architecture/sdk-architecture.md`, the push sections.

**Architecture:**
- **Commit path (no network I/O).** `PushOutboxContributor : ITaskWriteContributor` (package 05) runs inside the task write. For each committed event it reads the task's push configs and adds one `OutboxEntry` per config (`Kind = "push"`, `Lane = configId`). The body is formatted once per (event, payload format) by `IPushPayloadFormatter` and stored in a small envelope in `OutboxEntry.Payload`.
- **Delivery path.** `PushDeliveryService` (a `BackgroundService` in `Ambinder.A2A.Server`) is told about rows committed on this pod, and also polls. It claims rows with `IOutboxStore.TryClaimAsync`, and uses `ClaimDueAsync` as the recovery poll (Task 10). Then it loads the config, unprotects the credentials, builds the request, and settles the row: complete, reschedule, or dead-letter.
- **Keys.** `IPushSigningKeySource` wraps package 04's `A2ASigningKey`. There are three sources: ephemeral (Development), local keys (core), and Key Vault (`Ambinder.A2A.Azure.KeyVault`). The JWS is built by hand and signed with `await key.SignAsync(...)`.
- **Host pieces in `Ambinder.A2A.AspNetCore`.** The JWKS endpoint, `DataProtectionPushCredentialProtector`, and the `"a2a-push"` named HTTP client (connect-time SSRF check, or the proxy branch).
- **Receiver.** `Ambinder.A2A.Push.Receiver` depends on `Ambinder.A2A.Client`, ASP.NET Core and `Microsoft.IdentityModel.JsonWebTokens`. It does not depend on `Ambinder.A2A.Server` or `Ambinder.A2A.AspNetCore`. It implements the Client's `IA2APushWaiter` (B10).

**Tech stack:** .NET 10, ASP.NET Core (minimal APIs, Data Protection), `Microsoft.Extensions.Hosting`, `IHttpClientFactory`, `System.Diagnostics` (`ActivitySource`, `Meter`), `System.Security.Cryptography` (RSA, ECDsa, SHA-256), `Microsoft.IdentityModel.JsonWebTokens` (receiver only), `Azure.Security.KeyVault.Keys` (Key Vault package only), `Microsoft.Extensions.TimeProvider.Testing`, xUnit v3.

## Review focus

These are the places a reviewer should read most carefully:

1. **Crash between claim and complete.** The row stays claimed until `ClaimExpiresAt`, then another dispatcher re-claims it. The receiver sees the same `jti` and dedupes it. A lost claim (`A2AStoreException.Kind == Conflict` from `CompleteAsync`, `RescheduleAsync` or `DeadLetterAsync`) must be logged at Debug and dropped. It must not be retried or counted as a failure (Tasks 10 and 19).
2. **Dead-lettering frees the lane.** One bad event must not block later events of the same config. Other configs of the same task must never wait for it (Tasks 10 and 19).
3. **Same bytes on every retry.** The body comes from the stored envelope, never from re-serializing. `jti` = `OutboxEntry.Id` (Tasks 3, 7 and 10).
4. **The dispatcher needs the task's owner.** Package 05's `IPushConfigStore` takes a `TaskRef(Key, Owner)`, and the envelope fixed by the spec does not carry the owner. So the dispatcher reads `ITaskStore.GetAsync(entry.Task, ownerHint: null, ct)` to build the `TaskRef`. A missing task means its configs are gone too: complete the row with outcome `canceled`. This is an extra store read per delivery. The builder may cache owners per `TaskKey` in a small bounded cache. This is a plan-level choice, not a spec rule (Task 10).
5. **SSRF in proxy mode.** The pre-attempt resolve-and-check must run on every attempt, not only at config create. Redirects must stay off. The startup check for `ProxyEnforcesEgressPolicy` must apply outside Development (Task 9).
6. **Receiver order of checks.** Nothing is parsed or handed to the handler before the credentials (and the signature, when present) are verified. The JWKS is fetched only for a trusted `iss` (Tasks 15 and 16).
7. **Handler exception gives 500 and removes the dedupe mark**, so the redelivery runs the handler again (Task 16).

- `PushSignatureVerifier.VerifyAsync(string jwt, ReadOnlyMemory<byte> rawBody, PushSubscription? match, CancellationToken ct)` returns a `SignatureResult`: `Verified(jti, taskId, iss)`, `Invalid(reason)` or `Unverifiable`. The steps:
  1. Read the unverified `iss`. It must be in `TrustedAgents`, or equal the agent base URL recorded on the matched `PushSubscription`. Otherwise `Invalid("untrusted_issuer")`, and **nothing is fetched**. If there are no trusted agents and no agent on the subscription, return `Unverifiable` (spec step 3: rely on the credentials, and log a warning once).
  2. Get the keys from `PushJwksCache` for that agent.
  3. Check: `alg` is RS256 or ES256; `aud == WebhookUrl`; `exp` and `nbf` with `ClockSkew`; `exp - iat <= MaxTokenLifetime`; `iat` not in the future (beyond the skew); `body_sha256` equals base64url(SHA-256(rawBody)) with a fixed-time compare; `jti` is present; `task_id` is present.
- `PushJwksCache` (one per agent base URL):

## Task 16: Receiver endpoint pipeline (`MapA2APushReceiver`)

**Depends on:** Tasks 14 and 15.

**Files:**
- Create: `src/Ambinder.A2A.Push.Receiver/A2APushNotification.cs`, `PushVerification.cs`, `IA2APushHandler.cs`, `IPushBodyConverter.cs`, `PushReceiverEndpoint.cs`, `PushReceiverEndpointRouteBuilderExtensions.cs`
- Test: `tests/Ambinder.A2A.Push.Receiver.Tests/ReceiverEndpointTests.cs` (ASP.NET Core `TestServer`; no sockets)

**Interfaces (produces):**
- `public sealed record A2APushNotification` (`required` / `init` properties, no positional constructor): `TaskId`, `Event` (`StreamResponse`), `DeliveryId` (the `jti`, or the body hash), `Subscription` (`PushSubscription`), `Verified` (`PushVerification` flags: `Credentials`, `Signature`, `TaskId`), and `RawBody` (`ReadOnlyMemory<byte>`). It overrides `PrintMembers`, so `ToString()` shows no subscription secrets (package 02's secret-record rule).
- `public interface IA2APushHandler { ValueTask HandleAsync(A2APushNotification notification, CancellationToken ct); }`
- `public interface IPushBodyConverter { bool CanConvert(string contentType, ReadOnlySpan<byte> body); ReadOnlyMemory<byte> Convert(ReadOnlyMemory<byte> body); }` (a hook for package 15; nothing ships for it here). The exact shape is left to the builder (spec "Left to the builder": handler overloads). Keep it minimal, and flag it in the API diff.
- `MapA2APushReceiver(this IEndpointRouteBuilder, string pattern, Func<A2APushNotification, CancellationToken, Task> handler)`, plus an overload that resolves `IA2APushHandler` from DI. Both live in `Microsoft.AspNetCore.Builder` and return `RouteHandlerBuilder` or `IEndpointConventionBuilder`.
- The pipeline, in this order (spec "Request processing"). Every failure is a 401 with an empty body and a Warning log with a reason code (no secrets), unless noted:
  1. POST only (anything else gives 405, from routing). The body is read up to `MaxBodyBytes + 1`; more gives 413. The content type must be `application/a2a+json` or `application/json`; anything else gives 415.
  2. Credentials: `MatchAsync(Authorization, token header)`. No match, or missing credentials with `RequireCredentials`, gives 401.
  3. Signature: verify when the header is present. Require it when `Signature.Required`. `Invalid` gives 401. `Unverifiable` gives a warning once and continues.
  4. `IPushBodyConverter`: if one `CanConvert`, convert before parsing.
  5. Parse as `StreamResponse` with `A2AJson`'s typed accessor. It must have exactly one payload; otherwise 400.
  6. Task match: the payload task id (`task.id`, or `taskId` of a status update, artifact update or message) must equal the subscription task, or bind the wildcard. It must also equal the signed `task_id`, when there is one. Otherwise 401.
  7. Dedupe: the key is the `jti` when the signature was verified, else hex SHA-256 of (task id + body). A duplicate gives 200 `{"status":"duplicate"}`, and the handler is not called.
  8. Handler: success gives 200. An exception gives 500, plus `UnmarkAsync(key)` and an Error log.
