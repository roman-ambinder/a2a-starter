# Package 16: Cross-SDK Interop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, with every subagent on model `sonnet` (see "Execution notes" at the end). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CI-backed interop suite that proves `Ambinder.A2A.*` exchanges the same JSON and behaviour as the Python, JS and Java reference SDKs (both directions, all three transports), passes the official `a2aproject/a2a-itk` traversal and ACTS conformance runs, and catches JSON drift with golden fixtures before any container starts.

**Spec:** `docs/superpowers/specs/2026-11-03-sdk-16-interop-design.md` (approved 2026-11-03). Binding work plan: `docs/superpowers/specs/2026-11-03-sdk-00-work-plan.md`.

**Architecture:**
- **Golden fixtures** live in `tests/vectors/wire/v1.0/`, one JSON file plus one `.meta.json` per case. A catalog loader shared by linked source (`tests/Shared/WireFixtures/`) feeds two consumers: the fast fixture tests in `tests/Ambinder.A2A.Protocol.Tests` (normal unit job, no Docker) and the peer fixture checks in `tests/Ambinder.A2A.Interop.Tests`.
- **The interop driver** is `tests/Ambinder.A2A.Interop.Tests` (xUnit v3 on Microsoft.Testing.Platform). It expands a matrix (peer × protocol version × transport × direction × scenario) from `interop/matrix.json`. Peer `self` (our client against our server, in process) runs without Docker and is how every scenario is built test-first. Peers `python`, `js`, `java` run in containers via Testcontainers for .NET, built from `interop/peers/<peer>/Dockerfile`.
- **Direction A** (our client → peer server) uses `AddA2AClient(name, ...)` from package 10. **Direction B** (peer client → our server) starts our interop server in process on a real port, exposes it to containers, and runs `runner <scenario-id> <card-url> <transport>` in the peer container, which prints one JSON result object.
- **Ledgers:** `interop/known-divergences.json` (reviewed differences with upstream link and expiry) and the skip list inside `interop/matrix.json`. A difference not in the ledger fails; an entry that no longer reproduces fails; an expired entry fails.
- **Official ITK and ACTS:** an `itk/` agent (`itk/Ambinder.A2A.Itk.csproj`, public APIs only) plus `itk/run_itk.sh`, a shim over `a2a-itk`'s shared driver, pinned by `itk/ITK_VERSION`. Peers are pinned by overwriting the checkout's `matrix.yaml` with `itk/matrix.pinned.yaml` before the image build. ACTS reads `acts/sut-behaviors.yaml` at the repo root.
- **CI:** one workflow file `.github/workflows/interop.yml` with jobs `interop-smoke`, `interop-full`, `itk-pr`, `itk-nightly`, `acts`, callable from package 01's release pipeline.

**Tech Stack:** .NET 10 (`global.json`), xUnit v3 on Microsoft.Testing.Platform, System.Text.Json, Grpc.Tools/Google.Protobuf (instruction proto for `itk/`), Testcontainers for .NET (new central package version), Docker; Python 3 + `uv` (Python peer, a2a-sdk 1.3.0), Node.js + npm (JS peer, @a2a-js/sdk 1.3.0), Java 17+ + Maven (Java peer, a2a-java 1.5.0.Final); `a2aproject/a2a-itk` at `d53108aaf378a38eaff64ea39029a3d795591827`; GitHub Actions.

## Facts checked upstream (a2a-itk at d53108a) and resulting deviations

## Global constraints

- Spec A2A v1.0.1; proto `proto/a2a.proto` at tag `v1.0.1`.
- Principle 4: no reflection in `src/`. Test code (`tests/`, `itk/`, `interop/`) may use it.
- The interop test project and the `itk/` agent reference **public packages only**. No `InternalsVisibleTo` to them (spec principle 2 check). Task 10 adds a test that enforces this.
- No sleeps, no timers in scenario logic, no LLMs, no timing-based asserts (anti-goal). Waits use events or polling with a bounded deadline that only fails the test, never decides the result.
- No silent skips: every skipped cell is in `interop/matrix.json` with a reason; every tolerated difference is in `interop/known-divergences.json`.
- JSON comparisons go through JCS (package 04's `JsonCanonicalizer`), never string equality.
- Peer versions pinned with lockfiles (`uv.lock`, `package-lock.json`, `pom.xml` exact versions); base images pinned by digest.
- Peer containers: no secrets in env, no host mounts, built only from `interop/peers/<peer>/`.
- Third-party GitHub Actions pinned by commit SHA (package 01 §6). `permissions:` least privilege on every job.
- Helper scripts in Python run with `python3 -I` and need no extra packages (pattern from package 03).
- Do not change files under `src/` in this package. A bug found in `src/` is reported to the owning package (record it in `interop/known-divergences.json` only if it is a peer difference; our own bugs are fixed by 03 or the owning package, not tolerated).
- Commit after every task. Commit messages: conventional style (`test(interop): ...`, `ci(interop): ...`, `docs(interop): ...`).

```csharp
// tests/Shared/WireFixtures/WireFixture.cs
namespace Ambinder.A2A.Tests.WireFixtures;

public enum FixtureExpect { Roundtrip, ReadOnly, MustReject }

/// <summary>Sidecar <c>&lt;case&gt;.meta.json</c>.</summary>
public sealed record FixtureMeta(
    string Source,          // "spec-example" | "hand-written" | "peer-capture:<peer>@<version>"
    string SpecSection,     // e.g. "4.1.1" or "5.5"
    FixtureExpect Expect,
    string? Type = null,    // proto message name; defaults to the folder name
    string? Binding = null, // errors only: "jsonrpc" | "rest" | "grpc"
    string? Note = null);

/// <param name="Id">Path relative to the catalog root without extension, '/' separated, e.g. "Task/completed-with-artifact".</param>
/// <param name="Group">First path segment: a proto message name, "enums" or "errors".</param>
public sealed record WireFixture(string Id, string Group, string JsonPath, FixtureMeta Meta)
{
    public string ProtoType => Meta.Type ?? Group;
    public string ReadJson() => File.ReadAllText(JsonPath);
    public override string ToString() => Id; // readable theory row names
}
```

```csharp
// tests/Shared/WireFixtures/FixtureCatalog.cs
using System.Text.Json;
using System.Text.Json.Serialization;

namespace Ambinder.A2A.Tests.WireFixtures;

public static class FixtureCatalog
{
    /// <summary>Copied next to the test assembly by the csproj (see Step 3b).</summary>
    public static string Root { get; } = Path.Combine(AppContext.BaseDirectory, "vectors", "wire", "v1.0");

    static readonly JsonSerializerOptions MetaOptions = new()
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
        Converters = { new JsonStringEnumConverter(JsonNamingPolicy.KebabCaseLower) },
        UnmappedMemberHandling = JsonUnmappedMemberHandling.Disallow,
    };

    public static IReadOnlyList<WireFixture> Load(string root)
    {
        var list = new List<WireFixture>();
        foreach (var json in Directory.EnumerateFiles(root, "*.json", SearchOption.AllDirectories)
                                      .Where(p => !p.EndsWith(".meta.json", StringComparison.Ordinal))
                                      .Order(StringComparer.Ordinal))
        {
            var rel = Path.GetRelativePath(root, json).Replace('\\', '/');
            var id = rel[..^".json".Length];
            var meta = JsonSerializer.Deserialize<FixtureMeta>(File.ReadAllText(MetaPath(json)), MetaOptions)
                       ?? throw new InvalidDataException($"{id}: empty meta");
            list.Add(new WireFixture(id, id.Split('/')[0], json, meta));
        }
        return list;
    }

    public static IReadOnlyList<string> Validate(string root)
    {
        var problems = new List<string>();
        foreach (var json in Directory.EnumerateFiles(root, "*.json", SearchOption.AllDirectories))
        {
            if (json.EndsWith(".meta.json", StringComparison.Ordinal))
            {
                if (!File.Exists(json[..^".meta.json".Length] + ".json")) problems.Add($"orphan meta: {json}");
                continue;
            }
            if (!File.Exists(MetaPath(json))) { problems.Add($"missing meta: {json}"); continue; }
            try
            {
                var meta = JsonSerializer.Deserialize<FixtureMeta>(File.ReadAllText(MetaPath(json)), MetaOptions)!;
                if (string.IsNullOrWhiteSpace(meta.Source) || string.IsNullOrWhiteSpace(meta.SpecSection))
                    problems.Add($"meta needs source and specSection: {json}");
                if (json.Contains($"{Path.DirectorySeparatorChar}errors{Path.DirectorySeparatorChar}") && meta.Binding is null)
                    problems.Add($"error fixture needs binding: {json}");
                using var _ = JsonDocument.Parse(File.ReadAllText(json)); // must-reject files are still valid JSON text
            }
            catch (JsonException e) { problems.Add($"{json}: {e.Message}"); }
        }
        return problems;
    }

    static string MetaPath(string jsonPath) => jsonPath[..^".json".Length] + ".meta.json";
}
```

```csharp
/// <summary>Top-level messages and enums (with values) of a proto3 file. Test code; regex is enough for a2a.proto.</summary>
public sealed partial class ProtoInventory
{
    public required IReadOnlyList<string> Messages { get; init; }
    public required IReadOnlyDictionary<string, IReadOnlyList<string>> Enums { get; init; }

    public static ProtoInventory Load(string path)
    {

        var messages = TopMessage().Matches(text).Select(m => m.Groups[1].Value).ToList();
```

## Execution notes

- **How to run this plan:** use **superpowers:subagent-driven-development**. The controller session dispatches one fresh implementer subagent per task, then a spec-compliance reviewer subagent and a code-quality reviewer subagent per task, as that skill describes. **Every subagent (implementer, spec reviewer, code-quality reviewer, and any fix-up subagent) runs on model `sonnet`** — pass `model: "sonnet"` on every Agent dispatch. The controller does not implement tasks itself.
- **Branch:** one feature branch for the package (for example `feat/sdk-16-interop`) cut from `master` after package 01 merged; one commit per task (more is fine); one PR at the end, or one PR per phase if the owner prefers smaller reviews.
- **Order and parallelism:**
  - Task 0 first, alone. Its dependency report decides which tasks start BLOCKED.
  - Phase A (Tasks 1–8) in order. Task 3 and Task 8 may be BLOCKED (04, 10); continue with the others.
  - Task 10 Step 1 (project creation) before Task 9 Step 4.
  - Phase C (10–14) in order.
  - Tasks 16, 17, 18 (peer apps) are independent of each other and may run in parallel subagents after Task 15, each in its own git worktree (`isolation: "worktree"`), merged back in order.
  - Phase E (22–24) depends only on Tasks 0 and the dependency APIs, not on Phases B–D; it may run in parallel with Phase D in a separate worktree.
  - Task 25 after 14, 19, 23, 24. Task 26 last.
