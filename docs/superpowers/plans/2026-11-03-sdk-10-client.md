# SDK package 10: Production client — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task by task. Every subagent (implementer, spec reviewer, code-quality reviewer) runs on model `sonnet`. Steps use checkbox (`- [ ]`) syntax for tracking. See "Execution notes" at the end.

**Milestone:** M1.

**Goal:** Turn `Ambinder.A2A.Client` into the client a product team registers once and calls in a few lines. It covers DI and `IHttpClientFactory`, A2A-safe resilience, per-operation timeouts, interceptors, Entra-ready auth retry and step-up, wait for completion, stream resume, conversations, a caching card resolver, bounded reads, artifact assembly, and an opt-in gRPC transport in `Ambinder.A2A.Client.Grpc`.

**Architecture:**
- `A2AClient` is the only `IA2AClient` the SDK hands out. Each call runs one internal pipeline:
  1. lazy card and interface selection
  2. tenant rule and `A2A-Version`
  3. interceptors
  4. credentials and auth retry
  5. per-attempt timeout
  6. transport
  7. bounded read
  8. response info and tracing
- Transports are internal classes behind a public seam (`IA2ATransportFactory`, `IA2ATransport`). They only map requests to the wire and back. JSON-RPC and REST are in the core. gRPC is in `Ambinder.A2A.Client.Grpc`. 0.3 comes later from package 15.
- HTTP goes through a named `HttpClient` (`"A2A:{name}"`) from `IHttpClientFactory`. Its chain is:
  - `Microsoft.Extensions.Http.Resilience` (retry and circuit breaker, gated by a per-request retry-safety mark)
  - an attempt-timeout handler
  - one pooled `SocketsHttpHandler`
- Without DI, `A2AClient.ConnectAsync` builds the same chain around one process-wide `SocketsHttpHandler`.
- The wait, resume, conversation and artifact helpers are extension methods and classes on top of `IA2AClient`. So they work with any implementation, including package 12's fakes.

**Tech stack:**
- .NET 10, C# (repo `LangVersion`), nullable, `TreatWarningsAsErrors`
- `Microsoft.Extensions.{Http,Options,DependencyInjection,Logging}` and `Microsoft.Extensions.Http.Resilience` (Polly v8 underneath)
- `System.IO.Pipelines` (in the shared framework)
- `Grpc.Net.Client` and `Google.Protobuf` (`Ambinder.A2A.Client.Grpc` only)
- xUnit v3, `Microsoft.Extensions.TimeProvider.Testing` (`FakeTimeProvider`), Kestrel on `127.0.0.1:0` or package 12's `A2ATestServer` slice for wire tests

**Spec:** `docs/superpowers/specs/2026-11-03-sdk-10-client-design.md` (binding). Work plan: `docs/superpowers/specs/2026-11-03-sdk-00-work-plan.md` (binding; B6, B9, B10, B11, C11 apply here).

## Decisions this plan makes

Spec 10 "Left to the builder" leaves these open. The plan fixes them so execution is deterministic. Each one is called out in the PR description.

1. **Pipeline shape.** There is one internal `CallPipeline`. Interceptors and credentials are separate ordered steps, not one list.
2. **`A2ARequestHeaders`** is its own small, case-insensitive collection. The HTTP transports copy it to `HttpRequestMessage.Headers`. The gRPC transport copies it to `Metadata` with lowercased names. It hides `Authorization` from interceptors.
3. **Attempt timeout** is a `DelegatingHandler` (`A2AAttemptTimeoutHandler`) inside the retry strategy, not a Polly timeout strategy. It cancels only until response headers arrive. This keeps streams alive after headers, which Polly's timeout does not promise. The rest of a unary body read is bounded by the same timeout length, measured from the headers.
4. **gRPC handler chain.** The channel uses a sibling named chain `"A2A:{name}:grpc"`. It has the same primary handler settings (mTLS, keepalive, pooled lifetime) and no HTTP resilience handler, because gRPC retries come from the gRPC service config (spec: "gRPC uses a gRPC service-config retry policy"). Spec 10 says "the named client's handler chain". This is the one deliberate deviation. The owner approved it on 2026-11-03.
5. **Non-DI transports.** `A2AClientOptions.TransportFactories` (`IList<IA2ATransportFactory>`) lets `ConnectAsync` callers add gRPC. `Ambinder.A2A.Client.Grpc` adds `options.AddGrpcTransport()` next to `builder.AddGrpcTransport()`.
   - `TransportFactories` replaces 01's `A2AClientOptions.Transports`, and `GrpcTransportFactory` replaces 01's `GrpcClientTransport` (A10).
   - The two seams live side by side only from Task 12 to Task 19, so the gRPC tests keep running. Task 19 deletes the old one.
6. **`IA2AClient.Card` before the first call** throws `InvalidOperationException`: "The agent card has not been fetched yet; await CreateClientAsync or make a call first."
7. **Stream response info.** `OnResponse` fires for streams once headers arrive, before the first event. `StreamWithResumeAsync` yields `A2AStreamEvent` with `Kind` (`Event`, `Resumed`), `Event` and `Response` (`A2AResponseInfo`).
8. **Extended-card cache** is per client instance: an LRU of 100 identity keys. The client's own provider uses the key `""`.
9. **Jitter.** Backoff uses Polly `DelayBackoffType.Exponential` with `UseJitter = true`. `Retry-After` takes delta-seconds or an HTTP date, capped at 30 s.
10. **LRU** (card cache, extended-card cache, gRPC channels) is one internal `BoundedLru<TKey,TValue>` in `src/Ambinder.A2A.Client/Internal/`.
11. **`A2AConversation.LastResult`** is exposed (nullable).
12. **`IA2APushWaiter`** shape (B10; package 08 implements it):
    ```csharp
    public interface IA2APushWaiter
    {
        ValueTask RegisterAsync(PushSubscription subscription, CancellationToken ct);
        Task<StreamResponse> WaitAsync(string taskId, Func<StreamResponse, bool> until, CancellationToken ct);
    }
    ```
13. **SSE line buffer.** Lines are parsed in place from the `PipeReader` buffer. A line longer than `MaxEventBytes` fails as an oversized event.
14. **`A2AClientOptions.PrimaryHandler`** (`HttpMessageHandler?`, spec "Migration") replaces the primary handler for tests (in-memory servers). The SDK never disposes a handler it did not create.
15. **The name in messages.** Spec messages say "client '{name}'" and "agent '{name}'" (limits, circuit breaker, auth hint). The value is the client name given to `AddA2AClient`. Clients from `ConnectAsync` or `Create` are named `default`. Telemetry keeps `a2a.agent` = the card's name, as today.

## Review focus

Reviewers check these cases on purpose:

1. **A `SendMessage` whose response is lost after the server got the bytes.** It is never retried without `AllowSendRetry`. With the opt-in, it is retried only when there is no `taskId`, and with the same `messageId`. (Tasks 16, 22.)
2. **A blocking `SendMessage` that takes 2 minutes.** The 100 s `HttpClient` default does not cut it, and an attempt timeout does not cut a long stream after headers. (Tasks 15, 17.)
3. **A hostile agent:**
   - a 100 MB unary body
   - an SSE line with no newline
   - a 50 MB gRPC message
   - a 10 MB card
   - a 1 MB error body

   Each fails fast, naming the option, and memory stays bounded. (Tasks 5, 6, 11, 19.)
4. **A card whose security scheme points at an attacker's token URL or scope.** No provider sends a credential because of the card (07 rule). The selector picks providers only by scheme name and type. (Task 14.)
5. **Step-up by another identity (B6).** After the continuation, the wait never calls `GetTask` or `SubscribeToTask` with the continuation's credentials. (Task 22.)
6. **Per-call credentials without `CredentialCacheKey` (B11).** The extended card is never fetched or used. (Task 18.)
7. **Caller cancellation during a wait.** The result is `OperationCanceledException`, with no remote cancel by default (C11), and never `A2ATimeoutException`. (Tasks 15, 22.)
