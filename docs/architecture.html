A2A v1.0 · .NET 10 · Phase 1

A2A Reference Architecture

A reference repo your team copies from to build A2A agents and the clients that call them. Phase 1 runs entirely on one laptop: fake agents, a mock Entra, and in-memory state. It needs no keys, no cloud, and no Docker.

Phase 1: built Telemetry: built, off by default Phase 2: not built

Runtime: who talks to whom

Code: what you copy

Telemetry: where spans and metrics come from

Task lifecycle: the states a request moves through

Fixed local layout

:5100
MockEntra. Starts in Development only. Tenant a2a00000-…0001, audience api://a2a-demo.
:5200
AgentServer HTTP: cards at /.well-known/agent-card.json, JSON-RPC at /agents/{name}/jsonrpc, REST under /agents/{name}/rest.
:5201–5204
gRPC, one port per agent (echo, report, booking, secure). gRPC has no path to route on, so each agent gets its own port.
:5300
WebhookReceiver: checks the bearer credentials, the notification token, and the server's signed JWT on every push.
:18888
Aspire dashboard, only when you run samples/AppHost (OTLP on :18889). Local use only; the apps keep their ports above.
Phase 2
Real Entra, real LLM providers, durable storage, TLS, and multiple instances. These need configuration and, for storage, your own ITaskStore and IPushConfigStore; Phase 1 leaves the extension points in place. See production.md.
